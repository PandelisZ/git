Packfile laboratory

Compression changes representation, never identity.

Loose objects repeat headers and compress independently. Packs combine objects and may represent similar objects as deltas. Git reconstructs canonical content before verifying its OID.

Before packingSix independent loose-object files

Each object is stored in its own path. The path comes from the object ID; the file contains the zlib-compressed canonical object.

Clone and materialization laboratory

A clone is negotiation, object transfer, ref setup, then an optional checkout.

“Small clone” can mean fewer commits, fewer objects, fewer refs, fewer checked-out paths, or borrowed storage. Those are different mechanisms with different offline and integrity tradeoffs.

Materialized on disk

01

Shallow

Truncates commit ancestry and records boundary OIDs in .git/shallow. Deepen to cross the boundary.

02

Partial

Retains graph references to missing objects. A promisor remote supplies those objects on demand.

03

Sparse

Limits paths populated in the working tree. By itself it does not reduce downloaded history or objects.

04

Borrowed

Hardlinks or alternates avoid duplicate local storage. The safety properties depend on which mechanism is used.
