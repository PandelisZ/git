The model to hold

Jujutsu versions your files—and its own view of the repository.

Commits form the content history. Operations form a second DAG of repository states: visible heads, bookmarks, and each workspace’s working-copy commit.

First-class conflicts

A rebase can succeed with a conflict recorded inside the result.

Jujutsu stores a logical conflict with multiple terms. Markers are a working-copy materialization, not the canonical stored form. You can rebase, merge, or inspect the conflicted commit before resolving it.

Git backend and colocation

JJ adds a repository view above Git’s object store.

In a colocated workspace, `.jj/` and `.git/` are siblings. Commit IDs are Git commit IDs; bookmarks map to Git branches; snapshots and refs synchronize at command boundaries.
